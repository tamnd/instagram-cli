The first public release. `ig` is a single pure-Go binary that reads public
Instagram data and prints clean, pipeable records. It needs no API key, no
login, and no cookie. It reads the two public surfaces a logged-out client sees,
and it stays honest about which one answered.

## What you get

- **Read a profile.** `ig profile <username>` returns the full account record:
  the bio, the external link, the follower, following, and post counts, the
  verified and private flags, and the profile picture.
- **Read the recent posts.** `ig posts <username>` returns the recent posts on a
  profile, each with its shortcode, type, caption, exact like and comment
  counts, dimensions, and display url.
- **Read one post or reel.** `ig post <shortcode|url>` and `ig reel <url>` return
  a single media record from the page itself. They take a bare shortcode, a
  numeric media id, or a full `/p/` or `/reel/` link.
- **See the raw JSON.** `ig raw <username>` prints the upstream
  `web_profile_info` document, the source the profile and posts commands read
  from.

Records come out as table, JSON, JSONL, CSV, TSV, url, or raw. `--fields` picks
and orders columns, `--template` runs a Go template per record, and `-o url`
gives a clean link stream. Every record carries its own `url` and a `source`
field that says whether the counts are exact or rounded.

## Two planes, two reliabilities

Instagram serves the same public data through two channels that fail
differently, and `ig` is built around the difference.

The **SSR plane** reads the Open Graph tags a logged-out post or reel page ships
to a crawler. `ig post` and `ig reel` ride it and answer from anywhere,
including a datacenter IP. The like and comment counts on this plane are the
rounded numbers the page prints, so a record from it carries `source: ssr`.

The **API plane** calls `web_profile_info` for the full profile and the recent
posts as exact JSON, and a record from it carries `source: api`. That endpoint
answers from a residential session and is walled from a datacenter IP. When the
firewall gates a call, `ig` exits 4 with a clear message instead of pretending
it found nothing. See [troubleshooting](/reference/troubleshooting/) for the
full surface map.

## The shortcode codec

An Instagram shortcode is the media id written in base64url, so the mapping is
exact and reversible. `ig` uses it to keep its URL handling network-free: a
pasted `/p/{shortcode}/` link resolves without a fetch, and a numeric media id
turns straight into its canonical permalink. The codec lives in its own package,
`pkg/igcode`, so you can import it on its own:

```go
import "github.com/tamnd/instagram-cli/pkg/igcode"
```

## Install

```bash
go install github.com/tamnd/instagram-cli/cmd/ig@latest
```

Or grab a prebuilt binary from the release, or run the container image:

```bash
docker run --rm ghcr.io/tamnd/ig:0.1.0 --help
```

Every tagged version builds archives for Linux, macOS, Windows, and FreeBSD,
Linux packages (deb, rpm, apk), a multi-arch GHCR image, checksums, SBOMs, and a
cosign signature. The binary is pure Go, so there is nothing to install
alongside it.
